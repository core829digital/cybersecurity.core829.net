// Regole d'ingaggio

Sei regole che
non cambiano mai.

  • Autorizzazione scritta, sempre. Nessun test parte senza la lettera di incarico firmata dal titolare del sistema, con perimetro, date ed esclusioni.
  • Dominio verificato. Prima di iniziare controlliamo che il sito sia tuo, con un record DNS o un file sul server.
  • Perimetro e orari concordati. Testiamo solo ciò che è nell'incarico, nelle finestre orarie che scegli tu.
  • Test non distruttivi. Niente cancellazione di dati e niente attacchi di saturazione (DoS) che possano fermare il servizio.
  • Stop immediato. Hai un contatto diretto per sospendere il test in qualsiasi momento.
  • Massima riservatezza. Accordo di riservatezza, report cifrati, dati conservati in UE e cancellati a fine incarico.

// Quadro normativo

Un test che ti aiuta
anche con le norme.

Il report di un penetration test è uno dei documenti più concreti per dimostrare che la sicurezza viene verificata, non solo dichiarata.

Reg. UE 2016/679

GDPR, articolo 32

Chiede una procedura per testare, verificare e valutare regolarmente l'efficacia delle misure di sicurezza. Il report, con date e risultati, la documenta.

Dir. UE 2022/2555 · D.Lgs. 138/2024

NIS2

I soggetti coinvolti devono gestire i rischi informatici e valutare l'efficacia delle misure adottate, anche nella catena dei fornitori.

Reg. UE 2022/2554

DORA

Per il settore finanziario prevede test periodici di resilienza operativa digitale, inclusi test sulle applicazioni esposte.

Art. 615-ter c.p. · Art. 360 C. pen. RO

Accesso abusivo

In Italia e in Romania l'accesso non autorizzato a un sistema informatico è reato. L'autorizzazione scritta del titolare è ciò che rende il test legittimo.
